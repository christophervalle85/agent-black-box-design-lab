# Agent Black Box v0.8 — Native acceptance record (local prototype ACCEPTED)

**Status, October 19, 2026:** I completed the planned **on-device native acceptance** of my Apple Development-signed, macOS-only v0.8 prototype. The required-mode MCP gateway, signed XPC host/worker, native operator-only import/export, and the historical integrated Keychain RSA suite passed the acceptance checks below. **This is not a production security certification, a Developer ID/notarized distribution, or approval to merge `main`.**

**Evidence provenance:** I recorded results from my interactive Apple Silicon Mac terminal, not from a hosted runner or source inspection alone. These are local prototype acceptance outcomes; I have not independently reproduced them on another Mac. After my two new operator-negative diagnostics were added, I shared a complete local `npm test` transcript reporting **251 tests passed, 0 failed**. The transcript does not print an exact commit ID, so I attribute it to the updated local test suite without claiming a fresh run on the subsequent documentation-only rewritten HEAD. The separate interactive symlink and wrong-file tests both passed.

## Architecture and trust boundary

I keep the ordinary Node MCP policy/approval/audit controller **unsandboxed**. For the installed macOS `MCP_SANDBOX=required` path, fixed allowlisted synthetic `bbx-test-*.txt` note reads and exclusive writes execute through a separately Apple Development-signed native host and an App Sandbox XPC worker. The worker does not run arbitrary commands, access host-selected document paths, or receive unrestricted MCP file-transfer capabilities.

Separately, my opt-in, operator-only native import/export prototype uses a macOS Open/Save Panel, fresh biometric-only Touch ID, a bounded UTF-8 snapshot, signed XPC and an independent redacted HMAC metadata audit. It is **not** an MCP tool, not part of the installed required-mode worker, and not permission for agents to import arbitrary files.

The initial native installer was explicitly run once:

```bash

```

I **never** use `install-replace` automatically. It is a separate, explicitly authorized upgrade action, not part of routine verification. Neither this installer nor these tests provision, replace, or rotate my enrolled RSA Keychain controller key.

The installed signed worker reported its canonical container-owned `MCP_WORKSPACE_ROOT`. For a standalone gateway/controller invocation, I must configure that *exact verified root* in both environments, not `demo-workspace` or an inferred path. Missing or invalid signatures, trust pin, entitlements, peer checks, workspace binding, or handshake must **fail closed**.

## What I did **not** establish

- I have **not** produced Developer ID/notarized public distribution, a multi-user authentication service, or an independently protected Node controller. My parent Node process remains outside the XPC App Sandbox.
- My Team ID pin, Keychain software signing identity, HMAC key and audit files have **same-user compromise limits**. A local process with sufficient access may undermine their provenance. Local HMAC verification does not make evidence independently immutable.
- My `MCP_SANDBOX=required` worker permits only bounded synthetic notes. It does **not** expose operator import/export to legacy or modern MCP sessions, execute shell commands, or implement every MCP feature.
- My real-file operator prototype remains an opt-in experiment. I have not demonstrated full malicious-race resistance, durable real-document transaction recovery, independently trusted consent authority or crash-atomic end-to-end export/import.
- I have historical synthetic host/worker fault and cancellation evidence, but I have **not** re-exercised every fault variant against the newly installed required-mode binary.
- The separate Linux Bubblewrap design and existing tests remain in the project. I do **not** claim fresh Linux 7/7 isolated runtime acceptance from these Mac transcripts.

The installed required worker deliberately omits a cleanup operation. My acceptance tests may leave **disposable synthetic** notes in its sandbox Documents root; I do not remove that directory or automatically delete fixtures without reviewing the impact.
