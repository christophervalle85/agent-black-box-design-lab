Security boundaries **not established by v0.8**:

- The RSA credential is an existing software macOS Keychain identity; it has not been migrated to an independently provisioned, ACL-bound or hardware-backed signing service. A process with suitable same-user access could bypass our helper's policy.
- Node manages the HMAC secret and local audit files. Native independent recalculation rejects inconsistency, but **does not establish trustworthy provenance against a compromised Node process with that secret**. Same-user marker deletion, replacement and rollback are not mitigated.
- This synthetic RSA and native-controller pathway authorizes **fixed test-fixture** operations only; it does not establish a production review UI, arbitrary-file Keychain signing authority, independently trusted real-document commit receipt or a direct link to my separately tested operator file-picker flow.
- `NO_MARKER` does not prove nonexecution; `MATCHING_MARKER` does not prove actual import success. Uncertain outcomes must never automatically retry.
- GitHub Actions automatic runs are intentionally disabled for feature branch pushes to conserve account minutes. They still run on `main` and pull requests. Prefer local `npm test` and Mac native acceptance.
