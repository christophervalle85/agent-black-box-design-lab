# v0.9 — Security field guide

I started v0.9 with a standalone walkthrough at `/showcase`. My existing operational dashboard, approval routes, Node policy guard, HMAC store, MCP gateway and signed macOS XPC worker are unchanged.

## Run it

```bash
npm start
```

Open `http://127.0.0.1:4317/showcase`. The original dashboard remains at `/` and links into the guide. A local model, Apple signing certificate, or GitHub account is **not** required for this page.

## What is real, and what is illustrated

The field guide is a **read-only narrative** of six cases: sensitive-file denial, shell denial, one-use approval, path traversal, the macOS worker's actual OS sandbox-denial acceptance, and local audit tamper detection.

I deliberately keep walkthroughs and evidence separate. All timeline text comes from immutable local presentation fixtures; advancing a step only updates the browser DOM. The page does **not** run an agent, request a tool, prompt for Touch ID, produce audit records, make a native XPC request, or regenerate evidence. In particular, the OS sandbox scenario describes the separately compiled signed worker-source diagnostic from my v0.8 acceptance; it is not proof of a new test, and it does not claim a byte-identical installed worker.

Each scenario links to a document in the accepted v0.8 project. I use plain `textContent` and create DOM nodes instead of injecting scenario markup. I added only four exact-match static GET routes, all under the same content-security policy as my original dashboard.

## Layout scaffolding

I split the presentation into:

- `public/showcase-scenarios.mjs`: pure, fixture-backed cases and provenance links shared with Node tests.
- `public/showcase.html`: accessible page structure and disclosure.
- `public/showcase.js`: case selection, progress controls, and decision timeline. No backend writes or fetch calls.
- `public/showcase.css`: initial editorial styling, responsive layout, keyboard focus, and reduced-motion support.
- `tests/showcase-*.test.mjs`: fixture integrity, evidence scope, static route and API-isolation regressions.

My visual direction is an **editorial security field guide**: dark moss/graphite, sharp chartreuse highlights, quiet monospace metadata, and generous typographic contrast. This is only the layout foundation; typography, illustration, motion and brand personality can be refined without coupling the marketing presentation to the security-critical interface.
